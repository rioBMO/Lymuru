# 2026-11-18 — Per-user data directory + NSIS installer

## Problem

The app stores its database, logs, and Telegram session in `data/`, resolved
relative to the **current working directory**:

- `main.go` → `storage.Open("data/lymuru.db")`, `backend.InitLogger("data")`
- `app.go` → `NewDeezerSidecar("data", …)` (twice), `OpenConfigFolder()` uses `cwd/data`

The NSIS installer (`wails build -nsis`, install scope `machine`) puts the app in
`C:\Program Files\Lymuru`, and its shortcuts start the app with that folder as
the working directory. Normal users cannot write there, so `storage.Open` fails
and `log.Fatalf` kills the process. Because the binary is a GUI-subsystem
executable, the user sees nothing: the app just doesn't open.

## Changes

1. **`backend/datadir.go` (new)**
   - `ResolveDataDir()` → `$LYMURU_DATA_DIR` if set, otherwise
     `os.UserConfigDir()/Lymuru` (`%APPDATA%\Lymuru` on Windows).
   - `LegacyDataDirCandidates()` → `<exe dir>/data`, `<cwd>/data`.
   - `MigrateLegacyDataDir(dst, candidates)` → if `dst/lymuru.db` does not exist,
     copy the top-level files (db, `-wal`, `-shm`, `*.session`) from the first
     candidate that has a `lymuru.db`. The DB file is copied last via
     temp file + rename, so a failed copy never leaves a half-written DB that
     would block a retry. Originals are left untouched.
2. **`main.go`**: resolve the data dir → init the logger → migrate → open the DB
   with absolute paths. Startup failures are written to the log and shown in a
   native message box instead of exiting silently.
3. **`app.go`**: `App` stores `dataDir`. The sidecar and `OpenConfigFolder` use it.
4. **Settings UI**: the Deezer "Session File" hint stops saying `data/…`.
5. **Docs**: update the data path in `README-dev.md` and `AGENTS.md`.
6. **Installer**: install NSIS locally (`winget install NSIS.NSIS`) and build
   with `build.ps1` (`wails build -nsis`).

Out of scope: the Deezer sidecar script (`sidecar/deezload.py`) is not shipped
in the installer (same as today's portable EXE). The FFmpeg directory
(`~/.lymuru`) is unchanged.

## Testing strategy

- **Unit tests** (`backend/datadir_test.go`):
  - `LYMURU_DATA_DIR` override is respected and made absolute.
  - Migration copies db, wal, and session files; skips subdirectories.
  - Migration is a no-op when the target already has `lymuru.db`.
  - Migration is a no-op when the source and target are the same directory.
  - Migration with no candidate DB returns an empty source.
- `go vet ./...` and `go build ./...`.
- `wails build -nsis` must produce `Lymuru.exe` and `Lymuru-amd64-installer.exe`.
- Manual: install → launch from the Start Menu → confirm that
  `%APPDATA%\Lymuru\lymuru.db` and `logs\lymuru.log` are created.
  Note: on this dev machine, Smart App Control blocks unsigned binaries,
  including `go test` executables, so tests run under WSL/CI or on a machine
  without SAC enforcement.
